小手机备份转换器

在 330 / 兔k机、章鱼机、zz、弯弯、Float、糯叽机与两种糯米机之间转换备份。所有处理都在当前浏览器中完成。

本地离线处理
01

选择备份文件

支持糯叽机 v5、章鱼机 `.ee`，330/兔k机、zz、弯弯、Float、手抓糯米机与 csy 糯米机的 JSON / ZIP 备份。

02

转换目标

生成后请到相应小手机的原生“导入备份”功能中选择下载的文件。

03

附加选项新功能

默认只转角色、聊天、世界书、表情与基础设置。下面这些结构各家差别较大，需要时再打开。

记忆转换是刚加的，作者本人还没有实测过。 转出来的文件请先在目标小手机里试导入，确认记忆真的读出来了再删掉旧备份。 导入后读不到记忆属于已知风险，尤其是糯叽机 v5：它的记忆字段名是按读取端反推的，源码不在手上。 详见页面底部的注意事项。

导入会覆盖目标端的现有数据。请先在目标小手机里导出一份当前备份再导入。 转换范围与已知风险见注意事项。

注意事项（转换范围、记忆、表情包、隐私）

先说风险

  • 长期记忆和只转表情包是 2026.9.3 刚加的，作者本人还没有实测过。请先在目标小手机里试导入，确认数据真的读出来了，再删掉旧备份。
  • 导入备份会覆盖目标端的现有数据。导入前先在目标小手机里导出一份它自己的备份。
  • 转换只在浏览器里进行，不上传文件。但 API Key、Token、接口地址会按源备份原样保留到生成文件里，要分享给别人的话请先自行删除这些字段。

转换范围

默认会转：角色、群聊、消息记录、头像、世界书、表情包、基础设置。

打开开关才转：长期记忆。

不会转：各小手机独有的应用数据（商城、小游戏、记账、朋友圈、日记等）。这些没有跨项目的等价结构，硬塞过去只会变成一堆脏数据，所以不做，也不承诺无损迁移。

长期记忆（可选，默认关闭）

各家的记忆存法差别很大，转换器只搬记忆正文，按目标格式重建条目，全程不调用任何 AI。目标独有的字段用固定的降级规则补齐：标题取正文前 6 字，房间统一落客厅，情绪一律 neutral。

没有长期记忆系统：章鱼机、zz 小手机、弯弯小手机、miya 小手机、1900版uwu。选这些当目标时开关会自动灰掉。（几家看着像但不是：兔k机的「我们的回忆」是纪念日卡片，弯弯的 chatMemory_* 只是上下文条数，miya 的 memories 是相册回忆。）

向量只有在源和目标用同一个 embedding 模型时才搬得动，否则只搬正文，让目标小手机自己重新向量化：

  • csy ↔ 手抓：默认都是 BAAI/bge-m3（1024 维），可以直接搬。硅基流动的 Pro/ 计费档前缀视为同一个模型。
  • Float：默认是 text-embedding-3-small（1536 维），和上面两家的向量空间对不上，只搬正文。

只转表情包

只读源备份里的表情库，只写目标格式的表情字段，不碰角色和聊天。适合「只想把表情搬过去，不想动现有数据」的场景。

聊天记录里的表情是按名字引用的，所以转换时名字原样保留，导入后老消息才认得出来。

能这么用是因为 Float / csy / 手抓 的导入器是「字段存在才处理」的合并式，缺字段的文件只会更新表情库。330 / 兔k机 / yuan改uwu 不是：它们的导入会先把所有表清空再写入，拿只有表情的文件去导入会连角色和聊天一起清掉。想给它们只补表情，请在它自带的表情管理里逐个添加，或者改用上面的整包转换。

Float 的表情是按图集分组的（ai_phone_sticker_packs_v1）。转出去时会摊平成扁平列表；转进 Float 的图集分组暂时不做。

导入位置

  • 330 / 兔k机：生成 version: 3 的 330 兼容 JSON。兔k机走「从 330 格式导入」，330 走原生备份导入。
  • 章鱼机 / 1900版uwu：生成 Gzip 压缩的 .ee，走「导入数据」。
  • zz 小手机：设置里的「导入 JSON」。
  • 手抓 / csy 糯米机：设置里的「导入备份 (.zip / .json)」。
  • 糯叽机 v5：备份导入功能。仅保证通用聊天数据、角色、群聊、世界书和头像，专属应用数据会是空值或默认值。
  • 弯弯小手机：设置里的「导入备份」。世界书会写进弯弯的 lorebooks 配置，一律按全局注入，要绑定到单个角色请导入后自行调整。
  • Float 小手机：「数据管理 → 导入备份」。聊天、角色卡、设置分属不同模块，按模块勾选导入时要全部勾上才完整。
转换器不会访问网络，也不会读取任何小手机页面的本地数据库。只会处理你手动选择的文件。
