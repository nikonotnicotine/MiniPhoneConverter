# 小手机备份转换器

直接用新版 Chrome 或 Edge 打开 `index.html`，选择一个备份文件和目标小手机，点击“转换备份”后下载生成的文件。

支持的输入：

- 章鱼机导出的 `.ee` 完整备份。
- 糯叽机 v5 导出的 JSON 完整备份（外层 `data.structuredDB`）。
- 330 或兔k机导出的 JSON 完整备份、330 兼容 JSON、分块备份 JSON。
- 330 的“分片导出（推荐，打包为 ZIP）”生成的 `EPhone-Sliced-Backup-*.zip`。选择 ZIP 文件本身，不需要手动解压。
- zz 小手机导出的 `iphone-sim-config.json`，或包含该 JSON 的 `iphone-sim-config.zip`。
- 手抓糯米机导出的新版分片 ZIP（`manifest.json` + `metadata.json` + `stores/`）、旧版 `data.json` ZIP 或 JSON。
- csy 糯米机导出的 `data.json` ZIP 或兼容 JSON。ZIP 内的 `assets/` 图片会在转换时自动还原。
- 弯弯小手机导出的 JSON 完整备份（`appName: "弯弯"`）。
- Float 小手机导出的 ZIP 备份（`manifest.json` + `modules/`）。ZIP 内 `media/` 里的图片会在转换时自动还原。
- 曲曲机导出的 JSON 完整备份（`records` 记录流，`format: "quphone-backup"`）。图片存在 `blob` 记录里，转换时按 id 还原。

输出规则：

- 目标为“330 / 兔k机”时生成 `version: 3` 的 330 兼容 JSON。可在兔k机的“从 330 格式导入”中导入，或在 330 的原生备份导入中导入。
- 目标为“章鱼机”时生成 Gzip 压缩的 `.ee` 文件，可在章鱼机的“导入数据”中导入。
- 目标为“zz 小手机”时生成 zz 原生 JSON，可在设置中的“导入 JSON”中导入。
- 目标为“手抓糯米机”时生成 `version: 3` 的 SullyOS JSON，可在设置中的“导入备份 (.zip / .json)”中导入。
- 目标为“csy 糯米机”时生成 `version: 2` 的 SullyOS JSON，可在设置中的“导入备份 (.zip / .json)”中导入。
- 目标为“糯叽机 v5”时生成糯叽机兼容 JSON，可在糯叽机的备份导入功能中导入。仅保证通用聊天数据、角色、群聊、世界书和头像等字段；糯叽机专属应用数据会使用空值或默认值。
- 目标为“弯弯小手机”时生成弯弯原生 JSON，可在设置的“导入备份”中导入。世界书会写进弯弯的 `lorebooks` 配置，转换过来的世界书一律按全局注入，需要绑定到单个角色请导入后自行调整。
- 目标为“Float 小手机”时生成 Float 原生 ZIP，可在“数据管理 → 导入备份”中导入。聊天、角色卡、设置分属三个模块，按模块勾选导入时三个都要勾上才完整。
- 目标为“曲曲机”时生成曲曲机原生 JSON（`records` 记录流），可在它自带的导入备份功能中导入。世界书一律按全局注入写入，需要绑定到单个角色请导入后自行调整。

### 糯叽机新版兼容

糯叽机应用版本与备份格式版本不同：6.9.x 应用仍使用 `version: 5` 备份。转换到糯叽机时，角色使用角色页支持的 `type: "main"`，并生成同一用户下的当前身份、`userState.activeChatIds` 和置顶聊天状态。所有 `structuredDB` 表均写成记录数组，避免旧输出中 `type: "character"` 被角色页过滤、空对象 `userState` 无法恢复聊天列表的问题。

此适配已覆盖 330 和 yuan 改格式的回归测试；字段结构与新版公开前端的读取逻辑已核对。完整应用内导入仍需使用独立测试环境验收，专属应用数据与长期记忆的限制仍见下文。

转换只在浏览器中进行，不会上传文件。API Key、Token、接口地址等配置会按源备份原样保留；如果要分享生成文件，请在转换前自行删除这些字段。目标小手机导入备份会覆盖当前数据，请在导入前先保留目标端的原始备份。

## 转换范围

**默认会转**：角色、群聊、消息记录、头像、世界书、表情包、基础设置。

**打开开关才转**：长期记忆（见下）。

**不会转**：各小手机独有的应用数据（商城、小游戏、记账、朋友圈、日记等）。这些没有跨项目的等价结构，硬塞过去只会变成一堆脏数据，所以不做，也不承诺无损迁移。

## 曲曲机的两个降级

曲曲机没有开源，字段全部是从一份 v2 导出备份反推的。有两处必须降级，照实说明：

**气泡种类**。曲曲机的消息按 `kind` 分种类（`text` / `photo` / `sticker` / `call` / `transfer` / `systip` / `narration`），别家只有一条文本。图片和表情转出去时换成图片本体（目标端认 `data:image/` 前缀，照样显示成图片），其余种类降级成方括号文字：通话写成 `[视频通话] 通话时长 14 秒`，转账写成 `[转账] ¥520（已收款）`。转回曲曲机时，图片能对上表情库的会还原成表情气泡，其余的落成普通图片或文字 —— 通话和转账气泡**变不回来**。

**群聊**。手上这份备份里只有 `chat.contacts` 一张表，没有群聊结构，所以别家的群聊转进曲曲机时会摊平成一个普通联系人：每条消息前缀发言人名字（`阿音：在的`），群成员清单写进人设。聊天记录读得通，但不是真的群聊。

曲曲机也没有进“只转表情包”的目标列表：那个功能要求目标的导入器是「字段存在才处理」的合并式，曲曲机的导入行为没法确认，不敢拿用户的整机数据赌。要搬表情请用上面的整包转换。

## 长期记忆（可选，默认关闭）

各家的记忆存法差别很大，转换器只搬**记忆正文**，按目标格式重建条目，全程不调用任何 AI。目标独有的字段（csy 的标题、手抓的房间与情绪）用固定的降级规则补齐：标题取正文前 6 字，房间统一落客厅，情绪一律 neutral。

| 小手机 | 记忆存在哪 | 说明 |
| --- | --- | --- |
| 330 | `chats[].longTermMemory[]` | 纯文本 |
| 兔k机 | `history` 里 `type: "summary"` 的消息 | 纯文本。和 330 是同一个导出格式但读法不同，所以往这个目标写时两边各留一份，`summary` 消息带 `isHidden`，330 那边不会多出气泡 |
| yuan改uwu | `chats[].longTermMemory[]` | 纯文本 |
| 糯叽机 v5 | `structuredDB.memory[]` | 纯文本。**字段名是按读取端反推的**，源码不在手上，导入后读不到的话属于预期内的风险 |
| csy 糯米机 | `vectorMemories[]` | 带向量，重要度 1-10 |
| 手抓糯米机 | `memoryNodes[]` + `memoryVectors[]` | 带向量，重要度 1-10 |
| Float 小手机 | `ai_phone_memory_db_v1` 的 `memories` | 带向量，重要度 0-1（转换时自动换算） |
| 曲曲机 | `mem.<联系人id>` 文档的 `list[]` | 纯文本，权重 `s0` 是 0-1（转换时自动换算）。`state: "dead"` 的失效条目不迁移。**字段名是从一份导出备份反推的**，源码不在手上 |

**没有向量**：曲曲机的记忆条目有个 `vm` 字段但始终为空，只搬正文。

**没有长期记忆系统**：章鱼机、zz 小手机、弯弯小手机、miya 小手机、1900版uwu。选这些当目标时开关会自动灰掉。（几家看着像但不是：兔k机的“我们的回忆”是纪念日卡片，弯弯的 `chatMemory_*` 只是上下文条数，miya 的 `memories` 是相册回忆。）

**向量**只有在源和目标用同一个 embedding 模型时才搬得动，否则只搬正文，让目标小手机自己重新向量化：

- csy ↔ 手抓：默认都是 `BAAI/bge-m3`（1024 维），可以直接搬。硅基流动的 `Pro/` 计费档前缀视为同一个模型。
- Float：默认是 `text-embedding-3-small`（1536 维），和上面两家的向量空间对不上，只搬正文。

## 只转表情包

页面下方有一个独立的表情包转换模块，只读源备份里的表情库，只写目标格式的表情字段，不碰角色和聊天。适合“只想把表情搬过去，不想动现有数据”的场景。

聊天记录里的表情是**按名字**引用的，所以转换时名字原样保留，导入后老消息才认得出来。

能这么用是因为 Float / csy / 手抓 的导入器是“字段存在才处理”的合并式，缺字段的文件只会更新表情库。**330 / 兔k机 / yuan改uwu 不是**：它们的导入会先把所有表清空再写入，拿只有表情的文件去导入会连角色和聊天一起清掉，所以选这类目标时页面会直接警告。想给它们只补表情，请在它自带的表情管理里逐个添加，或者改用上面的整包转换。

Float 的表情是按图集分组的（`ai_phone_sticker_packs_v1`）。转出去时会摊平成扁平列表；转进 Float 的图集分组暂时不做。

使用方法：
1.导出你想转移小手机的备份。
2.点击网址：https://nikonotnicotine.github.io/MiniPhoneConverter/
3.上传备份 --> 选择转换到哪个小手机 ---> 开始转换 ---> 下载
